## 1. Purpose

Configure an AI provider, then either **generate a new widget from a prompt** or
**revise an existing AI widget**. Generated code is previewed in a real desktop window;
nothing is saved until the user reviews permissions and approves. Also supports loading
models, testing the connection, retrying repairs, and undoing a revision.

## 3. Component inventory and state

| State | Meaning |
|---|---|
| `config` | `AiConfig`: provider, baseUrl, model, width, height, hasKey |
| `provider` / `preset` / `baseUrl` / `model` / `width` / `height` | Editable local form |
| `apiKey` | Password field; cleared after save |
| `models` | Models returned by `listAiModels`; feeds datalist + select |
| `busy` | Label of the in-flight operation; drives sticky activity banner |
| `error` / `status` | Shown in the sticky activity banner when not busy |
| `prompt` / `instruction` | New prompt vs revise instruction (max 4000) |
| `result` | `AiGenerateResult` (ok/failure, manifest, logs, warnings, problems, repairs) |
| `previewLogs` / `previewActive` | Poll `getAiPreviewLogs` every 1 s |
| `approvalOpen` | Approval modal |
| `approvedPermissions` / `approvedHosts` | Editable subset, initialised to requested |
| `source` / `sourceLoading` | Existing widget metadata in edit mode |

Provider presets (hardcoded English labels): **Google Gemini** (Gemini), **Groq**,
**OpenRouter**, **Mistral** (OpenAI-compatible), **Ollama (local)**, plus **Custom**.
Changing provider picks its first preset and overwrites the base URL; editing the URL
sets preset to Custom. The provider select itself only has **Google Gemini** and
**OpenAI-compatible**; the preset select appears only for the latter.

Starters (chips): **Dotted battery and CPU**, **Pomodoro timer**, **Countdown to a
date**, **Week calendar**, **Habit tracker**, **Quote of the day**, **Weather for a
city**. Clicking replaces the prompt.

## 5. Behaviour and data contract

| Action | IPC |
|---|---|
| Load config | `getAiConfig()` |
| Persist provider/model/size | `saveAiSettings({provider, baseUrl, model, width, height})` |
| Key | `saveAiKey(provider, key)`, `removeAiKey()` |
| Models | `listAiModels()` |
| Connection | `testAiConnection()` → `{ok, modelCount}` or `{ok:false, message}` |
| Generate | `generateAiWidget(prompt)` |
| Revise | `reviseAiWidget(id, instruction)` |
| Repair | `repairAiWidget()` |
| Logs | `getAiPreviewLogs()` (poll 1 s while previewActive) |
| Close | `closeAiPreview()` |
| Approve | `approveAndSaveAiWidget({permissions, allowedHosts})` |
| Undo | `undoAiWidget(id)` |
| Edit source | `getAiWidgetSource(id)` |
| Cancel | `cancelAi()` |
| Policy link | `openExternal(url)` from a hardcoded host map |

Flow notes:
- Before generate/revise/load-models/test, the panel persists settings. **Save key**
  does not persist provider settings first, so a changed base URL can be out of sync
  until the next action.
- Generation creates a **real preview widget window on the desktop** via
  `ai-service` → `layout.openPreview`. The settings panel itself shows only a result
  card, metadata, problems/warnings, and the console; there is no inline visual preview.
- If generation succeeds, the approval modal opens automatically. Permissions and hosts
  default to everything requested; unchecking removes them from the saved manifest.
- Approving saves the widget and adds it to the desktop, closes the preview, and calls
  `onChanged` (App refreshes widgets/runtime). In edit mode the source refreshes.
- Failure can offer **Fix again** when `canRepair`; repairs may happen automatically up
  to a limit inside the service and are counted in `repairs`.
- Closing the preview discards the generated widget; there is no draft/history.
- Navigating away unmounts the panel and loses prompt/instruction/result state. A
  preview window may remain until closed by the user or a new operation.
- AI is usable only with a model id; Ollama is the only preset where a key is not
  needed.

## 6. Current styling notes

- `.ai-panel` is a vertical stack with 18 px gaps; no max width.
- Sticky status banner sits 8 px from the top of the scroll container, dark translucent
  background, green/accent text for status, red for error; spinner 13 px.
- Provider form is a 2-column grid; Base URL and Model span both columns; labels are
  11 px uppercase with tracking; inputs 9×10 px padding, 8 px radius; focus uses a
  1 px accent outline.
- Model field can show both a text input and a select (when models are loaded), plus a
  hint line; width/height are two number fields.
- Action rows wrap with 8 px gaps; buttons are enlarged inside `.panel` (8×13 px,
  12 px text) compared with global compact buttons.
- Starter chips are pill buttons with 11 px text.
- Privacy copy is two 11 px muted paragraphs.
- Result panel reuses `.panel`; problems are red-tinted lists, warnings amber; console
  is mono 11 px inside a bordered `details`.
- Approval modal: 480 px, 14 px radius, dark backdrop 72%, 12 px internal gaps;
  permission list is a bordered block with native checkboxes.
- The activity banner uses a hardcoded green border rather than `--ok`; modal backdrop
  has no blur (unlike Apps modals).

## 7. UX observations

1. **Provider setup dominates the page** even after it is configured. The form has 7
   fields and 5 actions; generation is below the fold at 620 px height.
2. **Five equal-weight actions** (save settings, save key, remove key, load models,
   test) create decision fatigue. There is no clear "connection is configured" state
   beyond a small badge and a hint.
3. **Save key does not save settings**; users can believe the selected base URL/model
   is active when it is not.
4. **No inline preview**: the result says "Preview ready" but the actual widget is on
   the desktop. In a compact window, users may not notice it, especially behind other
   windows. There is no thumbnail or "bring preview to front" action.
5. **Permission review is a generic checkbox list** in a modal, disconnected from the
   code/preview; there is no explanation of why each permission is needed, and no
   per-item risk hierarchy.
6. **Prompt state is fragile**: switching tabs loses the prompt/result; no draft,
   history, or examples that can be edited.
7. **No model discovery without a key/test**: the model field is empty by default and
   requires loading models or typing an exact id.
8. **Provider brand labels are hardcoded English** (Google Gemini, Groq, OpenRouter,
   Mistral, Ollama), while the provider select uses translated generic names.
9. **The edit flow cannot see the widget either**; "Edit with AI" shows only
   name/dimensions/history and a textarea. Undo is available but there is no version
   list or diff.
10. **Failure presentation** mixes machine problems, warnings, and logs; users cannot
    copy the error, and the console is a raw list.
11. **Approval modal keyboard handling is weak**: no Escape, no focus trap, background
    not inert; `Back` vs closing is ambiguous.
12. **Cancel only appears while generating/revising/repairing**; there is no cancel for
    model loading/testing, and no timeout feedback besides the sticky text.
13. **No indication of cost** beyond free-tier copy; no token/time estimate.

## 8. Design brief for the AI

Turn AI into a two-phase workspace: **Provider** (setup, collapsible once configured)
and **Studio** (create/revise with visual feedback).

- Collapse provider settings into a compact summary row (provider, model, key state)
  with an **Edit connection** expansion. Put Load models / Test connection inside the
  connection editor; make Save settings + Save key a single explicit "Save connection"
  or two clearly separated steps with pending state. Fix the semantics so what is shown
  is what is saved.
- Make the prompt the hero: large composer, starter ideas that append or can be
  edited, character count, Generate as the single primary action, cancel with elapsed
  time. Keep privacy copy but move it below the action or into a disclosure.
- Show the generated widget **inline** (reuse the `widget://` preview iframe, or a
  thumbnail with "Open preview window"), plus a clear status (previewing, approved,
  saved). Keep the external preview window if required, but make it discoverable.
- Design a permission review that is part of the result flow, not a surprise modal:
  show requested permissions/hosts as cards with plain-language explanations, a
  select-all/none, and a prominent "Save to desktop" that states what will be saved.
  Preserve per-permission toggles and host toggles.
- In edit mode, show the current widget preview and version context; let users write a
  change request, see progress, and compare/undo. If a visual diff is not possible,
  show a clear before/after summary.
- Make failure states actionable: structured problem/warning cards, copy error,
  collapsible console, and a single Retry/Fix action. Distinguish provider errors from
  generated-code errors.
- Keep all IPC calls, generation/repair/undo semantics, and the rule that nothing is
  saved before approval. No new backend fields or streaming unless marked future.
